    Workflows
    A workflow runs its steps one after another: SSH commands on one or more hosts, pauses, and waits until a host stops or starts answering ping or SNMP. Each step can branch to another step when it fails. Use it for updates and restart sequences where one device must be back before the next restarts. SSH connections are pinned to host keys you approve.

      UniFi
      What each Wi-Fi device experiences: signal, access point, band, speed, retries, roaming and UniFi's experience score, from the UniFi Network application on your gateway. It also names the devices in the Inventory. Read only; everything stays on your network.
      
          
      
            
      
            
      
            
      
          
      
          
      
            
      
              
        
                
      1. In UniFi (open your gateway's address in a browser) go to Settings, Admins & Users (on some versions Control Plane, Admins) and press Create New Admin.
        2. 
                
      2. Tick Restrict to local access only (a local account, not a UI.com one, and no two-step login: the monitor cannot type a code). Username: monitor, a long password. For the role choose View Only for the Network application. Create it.
        3. 
                
      3. Below: the gateway's address with https:// (for example https://192.168.1.1), the username and the password. Site: leave default; the name UniFi shows for it (such as Home) works too.
        4. 
                
      4. The gateway uses its own certificate. Press Fetch fingerprint and compare it with the one your browser shows for the UniFi page (padlock, certificate, SHA-256); when they match, press Test connection, then Save.
        5. 
                
      5. The Wi-Fi devices appear on each access point's Wireless tab. The weak-signal line is in Alert rules, Wi-Fi devices on weak signal.

      HTTPS
      How browsers connect to the monitor. With HTTPS the connection is encrypted, so passwords and stored secrets cannot be read off the network. Old http:// addresses and bookmarks are sent on to https:// automatically.
      
          
      
          
      
            
      
            
      
            
      
          
      
          
      
          
      
            
      The monitor makes and renews this certificate itself. Browsers warn about it once, because no public authority signed it: check that the fingerprint matches the one shown here, then continue, or download it and add it to your computer's trusted certificates so the warning goes away.
      
            
      
              
              
      
            
      
          
      
          
      
            
      A certificate from your own certificate authority, or one you got elsewhere, for the name you open the monitor by. PEM text: the server certificate first, then any intermediates; the key without a passphrase. The key is stored encrypted and never shown again.
      
            
      
              
              
      
            
      
              
              
      
            
      
          
      
          
      
            
      Plain HTTP: anyone on the network can read what passes, including passwords as you log in. Only for a network you fully trust.
      
            
      
          
      
          
      
        
      
        
      
          
      Proxmox
      A dashboard of your Proxmox host: nodes, VMs and containers with CPU, memory, network and disk history, storage, backups and failed tasks. Read only. Switched on, it gets its own page in the menu.
      
          
      
            
      
            
      
            
      Connects with a read-only API token. Nothing is fetched while it is off.
      
          
      
          
      
            
      
              
        
                
      1. In the Proxmox web interface: Datacenter, Permissions, API Tokens, Add. User: root@pam (or a user of its own), Token ID: monitor, keep Privilege Separation ticked, Add. Copy the secret: Proxmox shows it once.
        2. 
                
      2. Give the token read access. In the left menu click Permissions itself (the padlock line, not Users, API Tokens or Roles under it), then Add, and from the small list choose API Token Permission. Path /, API Token root@pam!monitor, Role PVEAuditor (read only), Propagate ticked, Add. The list then shows a line /, root@pam!monitor, PVEAuditor. Or in the Proxmox host's shell: pveum acl modify / --tokens 'root@pam!monitor' --roles PVEAuditor
        3. 
                
      3. Below: the address (https:// and the host's IP, port 8006), the token ID as root@pam!monitor and the secret.
        4. 
                
      4. Proxmox uses its own certificate. Press Fetch fingerprint and compare it with the node, System, Certificates, pve-ssl.pem, Fingerprint; when they match, save. The monitor then trusts that certificate and no other.
        5. 
              
      
              
      
                
      
                
      
              
      
              
      
              
      
                
      
                  
      
              
      
                Actions (optional): start, shut down, reboot and snapshots
                
      The token above only reads. For the buttons on the Proxmox page and the workflow step Snapshot a Proxmox guest, make a second token that may do just that. In the Proxmox host's shell:
      
                
      pveum role add MonitorActions -privs "VM.Audit VM.PowerMgmt VM.Snapshot"
pveum user token add root@pam monitor-actions --privsep 1
pveum acl modify /vms --tokens 'root@pam!monitor-actions' --roles MonitorActions
      
                
      The second command prints the secret once. Enter the token ID as root@pam!monitor-actions and that secret below.
